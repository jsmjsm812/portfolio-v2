01

작은 왕국

1인 개발 · 2026.08.25 ~ 09.06 · Unity 6, UGUI · 모바일 세로(9:16)

20초 안에 수호자를 배치하고 합치면 전투는 알아서 진행되는 로그라이트 타워디펜스입니다. 레벨업은 없고, 합성으로만 강해집니다.

전체 시연 영상 보기 (2:47)

제가 한 것

  • 준비 20초와 자동 전투가 반복되는 루프, 합성으로만 성장하는 규칙을 기획했습니다.
  • 수호자 10종, 침입자 8종, 구역 3곳 × 10웨이브를 전부 ScriptableObject 데이터로 만들었습니다. 새 수호자를 넣을 때 코드를 안 엽니다.
  • 타이틀, 로비, 배치, 전투, 결과, 도감, 상점 화면을 UGUI로 만들었습니다.
  • 전투 화면이 UGUI 오버레이라서 SPUM 캐릭터 프리팹(SpriteRenderer)을 그대로 쓸 수가 없었습니다. 그래서 에디터에서 애니메이션을 PNG 프레임으로 구워 데이터에 자동으로 연결하는 툴을 만들었습니다.
  • 밸런스는 시트로 웨이브별 체력과 화력을 계산해두고, 플레이해보면서 여러 번 되돌렸습니다. 배치 칸을 22칸에서 17칸으로 줄였다가 대신 웨이브 보상을 올린 것 같은 기록이 남아 있습니다.

제일 오래 붙잡고 있던 것

적이 안 죽는 게 아니라, 한 번에 죽는 게 문제였습니다.

테스트해보면 침입자가 체력바가 줄어드는 것도 안 보이고 그냥 사라졌습니다. 처음엔 체력이 너무 낮은 줄 알고 두 번에 걸쳐 크게 올렸습니다. 고블린 기준으로 20에서 110까지요. 그래도 똑같았습니다.

다시 보니 수호자의 공격 타이머가 배치되는 순간 0부터 시작하고 있었습니다. 준비 시간 20초 동안은 쏠 대상이 없으니 타이머만 계속 쌓이고, 웨이브가 시작되는 순간 모든 수호자가 같은 프레임에 한꺼번에 쏘는 구조였습니다. 타이머 시작값을 쿨다운 안의 랜덤값으로 바꾸니 해결됐습니다.

_attackTimer = Random.Range(0f, 1f / Mathf.Max(data.attackSpeed, 0.01f));

수치를 먼저 만질 게 아니라 발사 타이밍부터 봤어야 했습니다. 올려둔 체력 곡선은 원인을 고친 뒤에도 그대로 쓰고 있습니다.

뺀 것도 있습니다. 시야를 가리는 안개 기믹을 넣었었는데, 보기엔 그럴듯해도 플레이어가 배치를 바꾸게 만들지는 못했습니다. 그래서 빼고, 칸이 무너지는 붕괴 슬롯으로 바꿨습니다. 이 프로젝트에서 가장 중요했던 결정이었습니다.

Claude Code와 같이 만들었습니다. 장르와 규칙, 수치 결정, 플레이 테스트는 제가 했고, 정해진 설계를 코드로 옮기는 작업과 에디터 자동화 스크립트는 AI와 나눠서 했습니다. 레벨업을 다시 넣자는 식으로 기획과 안 맞는 제안이 나오면 규칙 문서에 적어서 다시 안 나오게 막았습니다.

02

라스트 글래디에이터

2인 팀 · 팀장 · 2026.05.28 ~ 06.26 (4주) · Unity 6 · PC

로마 콜로세움에서 1:1로 싸우는 소울라이크 액션입니다. 적 공격을 보고 가드할지 패링할지 매번 고르는 게 핵심이고, 스테이지는 6개입니다.

콜로세움 전투 13초 반복 · 전체 시연 영상 보기 (6:15)

제가 한 것

  • 컨셉, 전투 규칙, 스테이지 밸런싱을 기획했습니다. 처음엔 오픈필드에 무기 여러 개, 성장 시스템까지 있었는데 4주 안에는 못 끝낸다고 보고, 팀원을 설득해서 1:1 패링 전투 하나로 줄였습니다.
  • 플레이어와 적 전투를 맡았습니다. 이동, 구르기, 콤보, 가드, 락온, 포션까지 플레이어 조작 전부요.
  • 패링은 판정 0.2초에 성공하면 적이 2.5초 경직되고 3m 밀려나게 했습니다. 소울 시리즈 판정 구간(0.16~0.24초)을 참고해서, 연습하면 손에 잡히는 정도로 맞췄습니다.
  • 적 AI는 상태 15개짜리 FSM입니다. 피격이나 스턴이 끝나면 원래 하던 행동으로 돌아가도록 인터럽트 스택을 따로 뒀고, 플레이어 공격에 패링·회피·가드·무반응 중 하나를 가중치 랜덤으로 고릅니다.
  • 적 스탯, 패턴, 페이즈, 스킬 슬롯을 EnemyStageData 하나에 넣어서 적 하나를 추가할 때 데이터 파일 하나만 만들면 되게 했습니다.
  • 그 외에 암호화한 JSON 세이브/로드, 타이핑 효과와 TTS 내레이션을 붙인 스토리 컷씬, 결정타 킬캠을 만들었습니다.

제일 오래 붙잡고 있던 것

분명히 맞았는데 데미지가 안 들어가고, 경직된 적이 저를 때렸습니다.

처음엔 히트박스를 애니메이션 이벤트로 켜고 껐습니다. 그런데 이벤트가 가끔 빠져서 판정이 들쭉날쭉했습니다. 거기에 적이 공격하다 피격되면 무기 콜라이더가 켜진 채로 남아서, 경직 중인 적이 플레이어를 때리는 일도 생겼습니다.

두 개를 따로 고쳤습니다. 히트박스 타이밍은 애니메이션 이벤트 대신 코드에서 직접 잡았고(약공격 0.3초, 강공격 0.6초), 무기 콜라이더는 적이 공격 상태가 아니면 매 프레임 강제로 꺼지게 했습니다.

AI도 처음엔 Behavior Tree로 짜려고 했습니다. 하루 동안 프로토타입을 만들어보니 4주 안에 제대로 다루기 어렵겠다 싶어서, 팀원이랑 얘기하고 FSM으로 바꿨습니다.

03

위치 크로니클

5인 팀 · 팀장 · 2026.06.29 ~ 08.14 · Unity 6 · PC 3D

마녀학교에서 농사짓고 낚시하고 연금술로 만든 걸 들고 6속성 턴제 전투에 나가는 라이프 시뮬레이션 RPG입니다.

낚시 미니게임 13초 반복 · 전체 시연 영상 보기 (6:50)

제가 한 것

  • 세계관과 게임 전체 기획을 맡았고, 6속성 상성과 상태이상 규칙을 설계했습니다. 전투 코드는 팀원이 구현했습니다.
  • 라이프 시스템을 직접 만들었습니다. 방치형 파밍, 게이지를 버티는 낚시 미니게임, 요리와 포션을 만드는 연금술입니다.
  • 스킬 데이터 67종과 라이프 아이템 200종 넘는 걸 ID 체계로 묶고, 폴더를 읽어서 자동 등록하면서 ID 중복을 걸러내게 했습니다.
  • 팀장으로서 파일마다 주인을 정하는 규칙을 만들었고, Git LFS 문제가 생겼을 때 저장소를 새로 옮기자고 결정했습니다.

제일 오래 붙잡고 있던 것

앱을 끄면 작물이 안 자랐습니다.

파밍은 매 프레임 타이머를 깎는 방식이었습니다. 그런데 강제 종료하거나 절전으로 넘어가면 저장이 안 돼서, 다시 들어오면 자라던 게 0이 돼 있었습니다.

타이머를 없애고 씨앗을 심은 시각만 저장하게 바꿨습니다. 그리고 접속할 때 한 번만 계산합니다.

수확 개수 = Clamp(floor((지금 - 심은 시각) / 한 사이클), 0, 5)

경우를 나눠서 직접 확인했습니다. 바로 다시 들어오면 0개, 딱 한 사이클 뒤에는 1개, 100일을 방치해도 5개, 기기 시간을 과거로 돌려도 0개가 나오는지요.

낚시는 한 번 실수로 끝나지 않게 했습니다. 위험 구간에 닿자마자 실패시키지 않고, 거기 오래 머물 때만 줄이 끊기거나 물고기가 도망가게 했습니다. 스치듯 빠져나올 수 있어야 할수록 손이 는다는 느낌이 든다고 봤습니다.

시연 영상 코드 빌드는 용량이 14GB라 요청하시면 따로 보내드립니다.

저에 대해

대학에서는 호텔조리식당경영학을 전공했습니다. 멀티미디어학과를 복수전공하면서 뭔가를 직접 만들어 화면에 띄우는 게 재밌다는 걸 알게 됐고, 그게 게임 개발까지 이어졌습니다.

조리를 배울 때 몸에 밴 게 정해진 시간 안에 결과를 내는 습관입니다. 세 프로젝트 모두 처음 계획보다 범위를 줄였는데, 대신 셋 다 끝까지 만들었습니다.
